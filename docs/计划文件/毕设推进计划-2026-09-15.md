## 1. 前提变更与战略调整

### 1.1 三项新前提

| 前提 | 来源 | 影响 |
|---|---|---|
| 专业是**软件工程**，不是生物/生信 | 所有者 2026-09-15 确认 | 论文主张必须从「计算生物学」改为「软件工程」。这是**决定性**的好消息，见 §1.2 |
| **退出**中国国际大学生创新大赛 | 所有者 2026-09-15 确认 | 保密/知识产权顾虑解除，仓库可立即公开；比赛叙事、PPT 分支不再投入 |
| 本项目定位为**本科毕设交付**，更强的想法留到研究生阶段 | 所有者 2026-09-15 确认 | 目标从「科研价值最大化」改为「**以最高确定性通过答辩，且不透支时间**」 |

### 1.2 最重要的一条：换了专业，负结果从弱点变成正题

此前全部评估（`docs/深度调研/报告5-科研价值与论文可行性/`、`docs/深度调研/项目评估与优化方向-2026-09-11.md`）都在回答一个问题：**这些生物学结论能不能发表？** 答案是不能，因为：

- KD 可学性三条路线全证伪（ADR-0039/0040/0046）
- OE 外推判据 failed，正式关闭（ADR-0049）
- 跨背景外推主模型退化 7.68%，触发 No-Go（ADR-0047）
- 空间锚定场指标 30/30 出界，标定因协议偏差自我降级（ADR-0027/0043/0044）
- 证伪对照 3 判据不成立（ADR-0048）

**在软件工程学位论文里，这五条不是失败，而是论文的核心实证。** 论文要证明的命题不是「模型预测得准」，而是：

> 一套把预注册判据、不可变产物、字节级可重放和负结果保留写进**可执行代码**的软件机制，能够在真实科研流程中**阻止不成立的科学主张进入结论**。

上述五条就是这个机制**生效了五次**的直接证据。其中 ADR-0044（实际执行 105 次评估 > 预注册上限 89 次，系统自己把已得出的 `improved` 结论降级并禁用该 target）是**机制反向作用于作者自身**的案例，是整篇论文最有说服力的一页。

这条主张属于软件工程的以下方向，与专业完全对口：软件架构、软件质量保证、可复现性工程、配置管理与溯源、科学软件工程（Research Software Engineering）。

### 1.3 诚实的判断：这个项目**远超**本科软工毕设的及格线

按项目自身记录（数字需在 T2.1 中复核后才可写进论文）：核心包约 27,807 行 + 测试约 14,885 行、631 项测试、覆盖率 91%、零第三方依赖核心、GitHub Actions 双流水线、50 份架构决策记录、26 条 SHA-256 数据登记、Next.js 前端 + Cloudflare Worker + 可容器化 Python API 边界。

所以真正的风险**不是工作量不够**，而是这两条：

- **风险 A：选题被质疑「这是生物学不是软件工程」。** 缓解方式是 §4 P1——最早期就把论文定位交给导师确认，不要等写完。
- **风险 B：收不了口。** 8/19→9/12 的 24 天里产出 ADR-0035→0050，约 1.5 天一个。这个节奏继续下去，到答辩时会有 ADR-0080 和一篇没写完的论文。本计划的第一要务是**停止增建，转入收口与写作**。

## 2. 论文定位（需导师确认后锁定）

### 2.1 题目候选

1. 《面向可复现科学计算的分层契约架构设计与实现——以跨尺度生物仿真系统 M-GBA 为例》
2. 《跨尺度生物仿真系统中证据治理机制的设计与实现》
3. 《M-GBA：一个证据治理型可重放跨尺度仿真实验平台的设计与实现》

推荐 1 或 2：题目里同时出现「架构/机制」「设计与实现」，是软工毕设的标准句式，评审一眼能归类。

### 2.2 一句话主张（写进摘要与开题）

> 针对科学计算软件中「代码能跑 ≠ 结论可信」的工程问题，本文设计并实现了一套以分层契约、预注册门禁、不可变产物与字节级可重放为核心的证据治理机制，并在一个五层跨尺度生物仿真系统上完成实现与验证；该机制在真实实验流程中成功拦截了五类不成立的科学主张，其中一例为对作者自身已发布结论的自动撤回。

### 2.3 明确**不主张**（照抄进论文的边界声明章节）

- 不主张已构建真实虚拟细胞或数字生命
- 不主张任何 CAR-M 疗效、临床或生物学发现
- 不主张扰动预测方法上的先进性
- 不主张涌现

### 2.4 章节结构与素材映射

| 章 | 内容 | 现有素材 |
|---|---|---|
| 1 绪论 | 科学软件可复现性问题、国内外现状、本文工作与创新点 | 报告5 §4 的 Vivarium/PhysiCell/PhysiBoSS 对比；Fletcher & Osborne 的 seven challenges |
| 2 需求分析 | 功能需求（五层仿真、实验编排、报告生成、数据登记）；**非功能需求**（确定性、可审计、防篡改、可复现）——非功能需求是本文重点 | `可行性评估.md`、`核心原则.md`、`MVP计划.md` |
| 3 系统设计 | 五层契约架构、DTO/Protocol、多速率运行器、artifact 三层模型（manifest+raw+derived）、证据治理机制设计 | `架构设计.md`、ADR-0001/0007/0009 |
| 4 详细实现 | L0–L4 各层、runner、CLI、evidence-report 五阶段流水线、Web 交付层与 API 边界 | `src/mgba/**`、ADR-0050、`web/`、`services/lab-api/` |
| 5 测试与质量保证 | 631 项测试分类、覆盖率、篡改拒绝测试、冻结身份测试、确定性双跑、CI 流水线 | `tests/**`、`.github/workflows/` |
| 6 应用与机制有效性验证 | **本文的实证核心**：五次拦截案例 + 一次自我撤回案例 | ADR-0039/0040/0044/0046/0047/0048/0049、`artifacts/**` |
| 7 总结与展望 | 局限、未完成方向、后续工作 | `项目评估与优化方向-2026-09-11.md` §四 C |

> 第 6 章是与其他毕设拉开差距的地方，**不要写成「实验结果」，要写成「机制有效性验证」**。每个案例统一用四段式：预注册了什么 → 实际发生了什么 → 机制如何响应 → 若无该机制会发生什么错误主张。

- 任务：六条未见细胞系的 CRISPRi 零样本扰动预测
- 价值：唯一能拿到「锁定方法后只看一次的第三方评分」的途径
- **为什么默认不做**：VCC 要求全转录组预测，与六节点桥架构差距过大；对软工学位论文无加分；7 周投入会直接挤占 P2
- 若做：需新 ADR-0052 冻结「只跑一次、只看一次」协议；无论成绩原样登记

**O2 · 目标表征分辨率消融（需 ADR-0051）**
- 动机（这是我在核对 artifact 时发现的、项目自评未跟进的线索）：
  - 桥覆盖审计自述「约三分之二的宇宙基因在六节点向量中没有任何表达通道」（Norman 缺口 68.95%、Replogle KD 65.92%）
  - ADR-0046 把监督目标升到 56 维，但**通过规则仍只在六节点头上判**。而同一份实验记录载明：KD holdout 的 50 个集合维 MAE 为 centroid 0.016998 / ridge 0.016874 / **MLP 0.016516**（MLP 优于 ridge 约 3.6e-4）；而六节点头上 MLP 劣于 ridge 3.7e-5
  - **符号是反的，而冻结规则只看符号反过来的那一个**
  - 因此「KD 单敲低不可学」的严格表述应为「KD 在六节点桥的分辨率下不可学」；ADR-0048 的三组证伪对照检验了「管线会不会撒谎」，但没有一组检验「表征会不会把信号丢光」
- 设计：同数据、同 split、同三基线（质心 / ridge / MLP），只变目标空间三档——6 节点桥 / 56 维 Hallmark / 全基因（或 top-2000 HVG）log2FC；配按基因分块 bootstrap CI（沿用 ADR-0047 做法）；早停规则与两种结局的解释先冻结
- 对本毕设的价值：可作为第 6 章第六个案例——「证据治理机制发现了自身的盲区」，比前五个案例更进一层
- **重要限定**：3.6e-4 是描述性观察、未预注册，完全可能是噪声。**不得据此宣称 MLP 其实赢了**；该实验的目的是把一个脚注变成预注册结论，两种结局都要照实登记
- 成本：数据在盘、管线已存在、训练环境与显卡就位，工作量以天计
