# 同类软件对比基准（T2.4）

> 制定日期：2026-09-15｜用途：论文第 1.2 / 1.3 节与第 7.2 节
> 对比维度**全部为软件工程维度**，不比较生物学能力或科学产出。

---

## 一、方法与证据等级（务必写进论文，这是本表可信度的前提）

本表的每一格标注证据等级，**不允许出现无来源的判断**：

| 标记 | 含义 |
|---|---|
| **✔** | 有直接公开证据支持（论文、官方文档、仓库 README/Release 明确记载） |
| **◐** | 部分支持，或仅在某些场景下支持 |
| **—** | **在已查阅的公开资料中未见记载**。**注意：这不等于该软件不具备该能力**，只表示公开资料未强调 |
| **?** | 需要实际安装运行才能判定，本轮未验证 |

**方法学声明（论文中必须写）：** 本对比基于公开文献与代码仓库的文档核对，**未对全部对手软件做实际安装与运行验证**。因此 "—" 只能解读为"未作为公开特性被记载"，不能解读为"不具备"。这一限制在第 7.2 节局限性中如实声明。

**采集日期：** 2026-09-15。各仓库的 star/fork/release 数为该日快照，论文中需注明。

## 二、对比对象

| 简称 | 全称 | 语言 | 许可证 | 定位 |
|---|---|---|---|---|
| **M-GBA** | Multi-scale Graph Biological Architecture | Python 3.11+（核心零依赖） | MIT | 本文工作：证据治理型跨尺度仿真测试床 |
| **Vivarium** | Vivarium Core | Python | Apache-2.0 | 异构模型组合引擎与接口 |
| **PhysiCell** | PhysiCell | C++ | BSD-3（需复核） | 3D 多细胞物理仿真器 |
| **PhysiBoSS** | PhysiBoSS / PhysiBoSS 2.0 | C++ | 同 PhysiCell | 布尔信号网络接入 PhysiCell 的多尺度扩展 |

### A 组 · 架构与接口

| A2 层间接口是否**显式契约** | ✔ 正式 DTO/Protocol，带版本与指纹字段 | ✔ ports + schema（Store 决定更新语义） | ◐ 通过数据结构与 XML 约定 | ◐ | ◐ | 不适用 |
| A3 是否**强制相邻层、禁止跳层** | ✔ 架构 + 测试双重强制 | — | — | — | — | 不适用 |
| A4 多速率 / 多时间尺度调度 | ✔ L0/L4 慢时钟 + L1/L2/L3 快时钟 | ✔ 多时间尺度、可并行多 CPU | ✔ 多时间步 | ✔ | ✔ | 不适用 |

> **B8 是本文的劣势**：MultiCellDS 是社区标准，M-GBA 用的是自定义 schema，互操作性更差。如实写。

## 四、逐对象要点（第 1.2 节写作素材）

**Vivarium（Agmon 等，Bioinformatics 2022）**
核心抽象为 Process（含参数、更新函数与端口的模块化模型）、Store（持有状态变量与决定更新语义的 schema）、Composite（由 Topology 二分网络连接的 Process 与 Store 集合）、Compartment 与 Hierarchy。支持多时间尺度与多 CPU 并行。Apache-2.0，Python，CI 覆盖 docs/pylint/pytest/mypy。
**与本文关系：** A1/A2/A4 上 Vivarium 更成熟，是本文架构设计的直接参照对象，**不是被本文超越的对象**。本文与之的区别在 A3（禁止跳层）与整个 C 组。

**PhysiCell（Ghaffarizadeh 等，PLOS Comput Biol 2018）**
C++，3D 细胞力学、迁移、死亡、增殖与扩散底物，可扩展到 10⁵–10⁶ 细胞量级。XML 配置，MultiCellDS 输出。**可复现性建设持续推进中**：v1.14.0 起支持显式整数随机种子或 `system_clock`，并引入基于 GitHub Actions 的系统测试包；v1.14.1 起把种子写入 `output/random_seed.txt`。
**与本文关系：** 性能与生物真实性远超本文。可复现性上双方方向一致但深度不同——PhysiCell 做到"种子可控且落盘"，本文做到"双跑字节级一致且作为测试门禁"。**必须承认 PhysiCell 正在这条路上主动推进，不能写成静态的对立面。**

**PhysiBoSS / PhysiBoSS 2.0**
把 MaBoSS 布尔信号网络接入 PhysiCell ABM，研究遗传/环境改变如何传播到多细胞行为；2.0 版本强调解耦与模型无关设计。
**与本文关系：** 与本文的"跨尺度传播"问题最接近的先例。第 1.3 节必须正面处理："跨层传播"本身不是本文的新颖点。

**CompuCell3D**
C++ + Python，多细胞虚拟组织建模环境，`.cc3d` 配置，Azure Pipelines CI，3,779 次提交，含 Player/Twedit++ 图形工具与 conda 分发。
**与本文关系：** 工程成熟度与用户可及性的对照组，凸显本文在 D12/D13 上的不足。

**Sumatra（Davison 等，约 2009 起）**
"计算科学的电子实验记录本"，自动记录每次运行的代码（版本控制项目记录仓库 URL 与 revision）、参数文件与命令行、运行平台、运行原因与结果摘要。设计哲学是"尽可能自动记录"。
**与本文关系（第 1.3 节的关键一段）：** Sumatra 及 DVC、MLflow 一类工具解决的是**记录**问题——事后可以查到发生了什么；它们**不施加约束**：不会拒绝运行、不会因为超预算而撤回结论、不会阻止你第二次查看测试集、不会阻止你删掉失败的那次。本文的机制是 **fail-closed 的执行期约束**，而非事后记录。这是一个窄但真实的区别。

## 五、必须处理的文献风险（否则第 1.3 节会被击穿）

答辩或审稿时最可能被指出的先例，**论文必须主动提及并区分**：

| 先例 | 风险 | 本文的区分 |
|---|---|---|
| Sumatra / DVC / MLflow / Weights & Biases | "实验追踪早就有人做了" | 它们记录，不强制；无预注册、无测试集消费、无声明分级、无结论撤回 |
| OSF 预注册 / ADEMP-PreReg（仿真研究预注册模板） | "预注册也早就有了" | 那是**给人看的文档协议**；本文把预注册判据写成**可执行代码**，由软件在运行时强制 |
| 《Pre-registration of mathematical models》（Mathematical Biosciences, 2022） | "数学模型预注册已有专文讨论" | 同上：方法学倡议 vs. 工程实现。**此文必须在写作前通过学校图书馆拿到全文核实**，不得只凭标题引用 |
| W3C PROV / 工作流溯源（Snakemake、Nextflow） | "溯源标准已存在" | 溯源记录血缘关系，不判定结论是否成立 |
| 可复现构建（reproducible builds） | "字节级确定性是老概念" | 本文借用该概念并应用于科学结论层，**如实注明这是借鉴而非发明** |

**收口表述建议（第 1.4 节）：**

> 本文不主张首创可复现性工程或预注册方法。本文的贡献在于：把此前分散在实验追踪工具（记录导向）与科研方法学倡议（文档导向）中的要求，**统一实现为跨尺度仿真系统内部的 fail-closed 执行期门禁**，并给出该机制在真实研发过程中生效六次（含一次撤回作者本人已发布结论）的完整记录。
