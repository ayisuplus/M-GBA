# ADR-0007：WP7 多速率五层运行器与检查点

> 状态：已接受  
> 日期：2026-08-18  
> 作用范围：WP7 CrossScaleRunner、逐 tick trace、检查点与运行 artifact

## 背景与研究问题

当前 `ReferenceCrossScaleRunner` 只执行一次 L0→L4 映射，每层都从空上一状态开始。各层虽然已经有独立动力学，主运行链却还不能表达状态持续、相邻反馈、不同更新频率或暂停恢复。WP7 要回答：

> 如何在不跳层、不引入 L4 微观导演的前提下，把五层 reference model 组合成可复现、可暂停、可恢复的时间演化系统？

旧单 tick Runner 继续作为契约回归基线。WP7 新增 `MultirateCrossScaleRunner`，不在本阶段实现 L4 环境控制、STEN rewiring、随机调度或并行执行。

## 冻结调度

快速逻辑时间从 1 开始。默认参数为：

| 参数 | 值 | 含义 |
|---|---:|---|
| `l0_interval` | 5 | L0 在 `1, 6, 11, ...` 更新，其余 tick 保持上一转录状态 |
| `l4_interval` | 10 | L4 在 `1, 11, 21, ...` 产生规范窗口观测 |
| `max_total_ticks` | 10000 | 单个实验允许完成的最大累计 tick |
| `max_cells` | 256 | reference runner 允许的最大 Cell 数 |
| `max_events_per_tick` | 32 | 每 tick 的转换事件与 L0 扰动事件总预算 |

每个 tick 按以下确定顺序执行：

```text
1. L0：到期则用上一 TranscriptState 更新，否则保持
2. L2(t-1) → MolecularInput(t)
3. L1：用当前 TranscriptState 与上一 MolecularState 更新
4. L3(t-1) → LocalEnvironment(t)
5. L2：用当前 MolecularState、局部环境与上一 CellState 更新
6. L3：用当前 CellState/CellAction 与上一 TissueState 更新
7. L4：到期时观察当前 TissueState
```

L1、L2 和 L3 每个快速 tick 都更新。所有 Cell 在同一层内按同步语义读取上一层/上一时刻快照，Cell ID 始终排序且一一对应。

## 相邻反馈

WP7 只闭合已经存在的相邻边界：

- 首 tick 的 `MolecularInput.local_signal = 0`；之后由同 Cell 上一 `CellState.activation` 转换，形成 L2→L1 的正式快速反馈；
- 首 tick 使用场景初始 `LocalEnvironment`；之后由上一 `TissueState` 的同 Cell 节点转换，形成 L3→L2 的局部环境反馈；
- L0 仍只接收显式外部 `RegulatoryInput`，不从 L4 或 L3 跳层读取状态；
- L4 在 WP7 仍是纯观察器，不把 `PhenotypeWindow` 或结局写回下层。

这不是完整的宏观反馈闭环。L4→L3 受约束慢反馈属于后续独立工作包。

## 逐 tick trace

每个 `MultiscaleTickTrace` 保存：

- 逻辑时间、L0 是否更新、L4 是否按计划观测；
- 当前 L0、L1 输入/L1、L2 局部环境、L2 状态/动作、L3 状态；
- 本 tick 的可选 L4 状态；
- 本 tick 的 L0 扰动事件和相邻层 `LayerTransitionEvent`；
- 本 tick 事件计数。

即使 L0 本 tick 保持，L1 仍正式消费当前持有的 `TranscriptState`，因此 L0→L1 转换事件不会消失。L3→L4 事件只在计划观测 tick 产生。

运行历史使用确定性哈希链：

```text
history_digest(t)
  = digest(previous_history_digest, MultiscaleTickTrace(t))
```

相同 manifest 和执行 tick 必须得到相同 trace 与最终历史摘要。

## 终点观察与窗口

如果用户请求停止的 tick 不是计划 L4 tick，Runner 会从最终 `TissueState` 生成一个只读 `terminal_observation`，用于本次返回值的最终窗口摘要：

- 终点观察不进入规范 tick trace；
- 不进入 checkpoint 的计划 L4 历史；
- 不改变哈希链或任何下层状态；
- 恢复运行时不会把上一次暂停边界误当成生物学事件。

因此，把同一实验一次运行到 tick 100，或在 tick 13 保存后再运行 87 tick，必须得到完全相同的最终 checkpoint、历史摘要、终点观察和窗口。

## Checkpoint

Checkpoint 只允许在完整 tick 边界创建，保存：

- schema 版本、实验 ID、已完成逻辑时间和五层模型版本；
- 当前 L0/L1/L2/L3 正式状态；
- 所有计划 L4 观测；
- 当前历史哈希链摘要。

恢复前必须重新从场景、扰动、Runner 配置和五层模型版本构造 manifest。实验 ID、模型版本、Cell 身份或时间不一致时拒绝恢复。Checkpoint 使用纯 JSON；冲突路径不得静默覆盖。

运行 artifact 同样是纯 JSON，包含 manifest、逐 tick trace、终点观察、窗口摘要、checkpoint ID 和历史摘要。它是只读证据；真正恢复从 checkpoint 进行。

## 预算与失败原子性

运行开始前检查累计 tick 和 Cell 数预算。每 tick 生成转换事件后检查事件预算。任何预算、契约或模型错误都会在返回新 checkpoint 前失败；调用者不得把失败过程视为已提交状态。

`max_events_per_tick` 统计本 tick 的 `LayerTransitionEvent` 与 `L0PerturbationEvent`，不把 DTO 字段数伪装成事件数。性能和内存优化属于真实 profiling 后的工作，不在此阶段引入并行框架。

## CLI

保留：

```text
mgba run
```

作为单 tick 契约演示。新增：

```text
mgba simulate --ticks 100
              [--checkpoint-in PATH]
              [--checkpoint-out PATH]
              [--trace-out PATH]
```

`--ticks` 表示本次新增执行的 tick 数；checkpoint 恢复后继续累加。CLI 默认打印紧凑最终摘要，只有显式 `--trace-out` 才写完整逐步 artifact。

## 验收与失败判据

1. 默认配置连续运行 100 tick，L0/L4 到期时间和每 tick 层顺序与本文完全一致；
2. L1/L2/L3 上一状态持续传入，L3 节点生成下一 L2 环境，上一 L2 状态生成下一 L1 输入；
3. 同一 manifest 的两次 100 tick 结果、历史摘要和 checkpoint 完全相同；
4. 一次运行 N tick 与在任意完整 tick 暂停后恢复到 N 的最终 checkpoint、摘要和窗口完全相同；
5. checkpoint/trace artifact 是可直接读取的 JSON，冲突覆盖、损坏 schema、混合实验和模型版本必须失败；
6. 超过 Cell、累计 tick 或每 tick 事件预算必须失败；
7. 每个 tick 只出现相邻层转换，L4 非到期 tick 不产生规范 L3→L4 事件；
8. 默认修复敲低仍只从 L0 进入，并沿 L1→L2→L3 改变终点 L4；
9. `mgba simulate --ticks 100`、全部单元测试、单 tick CLI 和 STEN smoke 全部通过。

## 备选方案

1. 循环调用单 tick Runner：每次清空上一状态，属于伪时间演化，拒绝。
2. 所有层每 tick 同频更新：实现更简单，但无法验证多速率调度，拒绝作为 WP7 默认。
3. 暂停时强行写入计划 L4 状态：会让结果依赖人为分段位置，拒绝；采用只读终点观察。
4. 使用 pickle 保存 checkpoint：不可审计且不适合长期 artifact，拒绝。
5. 在此阶段加入线程/进程/Ray：没有性能证据，且会破坏确定性基线，推迟。

## 影响、局限与回退

- 新 Runner 与旧 `ReferenceCrossScaleRunner` 并存，任何调度问题都可回退到单 tick 契约基线。
- reference 轨迹仍无真实时间单位，默认频率是工程冻结值，不是生物学测量。
- Checkpoint 恢复保证确定性计算状态，不保证跨代码版本自动迁移；schema/model 变化必须显式适配。
- 当前没有 L4 下行反馈、随机种子分布、层级消融或统计显著性，因此完成 WP7 仍不构成涌现或验证结果。
