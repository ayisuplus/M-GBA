# ADR-0020：自动实验调度器（Autolab 元层，Phase 1）

> 状态：Accepted
> 日期：2026-08-21

## 背景

1. 项目所有者提出将系统升级为"自动化实验室"式闭环：自动提出假设、设计实验、读取结果、进入下一轮。前沿核实（检索时间 2026-08-21）：self-driving lab 在问题收紧时真实有效（[2026 hype-vs-reality 评估](https://www.robotonrails.com/pages/guides/self-driving-lab-2026-hype-vs-reality.html)、[闭环科研综述](https://victorchen96.github.io/auto_research/auto_research_survey.pdf)），主流痛点是被研究系统不可复现——M-GBA 的全确定性、manifest 哈希链与冻结实验协议恰好补上这一缺口。
2. 架构边界（与所有者确认）：自动化的对象是"做实验"，不是五层系统本身。Autolab 是**元层工具**，坐在 L0–L4 之外：只读运行结果，唯一执行通道是经既有正式边界（本阶段为 WP8 式层内静态替换）提交实验配置，永不进入 tick 循环。核心原则与 MVP 计划的研究主线不变。
3. 所有者决策：Phase 1 只做**确定性**调度器（无 LLM、纯本地、可复现），预留 LLM 提案接口；定位为实验工具层。
4. 两个先验风险写入设计：循环自证（假设在产生它的参考模型上"被验证"，结论只挂 reference-model 级）与指标投机（ADR-0018 已实测盒边效应，评估门必须冻结且多维）。

## 决定

1. 新增 `mgba/autolab.py`：元层调度核心 `AutolabSession`，**不 import runner**（ADR-0018 注入式模式），评估器由调用方注入；测试用脚本化评估器，CLI 用真实配对运行（WP8 `_compare_runs`）。
2. 预注册假设注册表（`configs/experiments/autolab_screen.json`）：假设 = 结构化可执行条目，Phase 1 只支持 `layer_static_swap`（L1/L2/L3 静态替换，复用 `_load_multirate_runner` 变体族）；未知 kind/层 fail-fast。调度器不能发明新实验。
3. 冻结选择策略 `screen_then_confirm`：筛选轮按冻结优先级序（priority 降序、id 升序）在 `probe_ticks` 评估全部注册假设 → 按冻结效应标量排名 → 确认轮把 top-`confirm_top_k` 在更长的 `confirm_ticks` 地平线复评。第二轮选择由第一轮测量驱动（闭环成立），但规则先验固定，同配置位级可复现。
4. 冻结效应标量：每 seed 取 WP8 有向终末 L4 五指标的平均绝对值，假设效应 = 跨 seed 均值。任何后续阶段不得悄悄重定义"效应"。
5. 预算护栏：`budget` 为总评估次数上限；耗尽时未评估假设记入 `pending`；已筛选未确认者不混入 pending（语义分离），会话如实报告无确认 leader。
6. 决策留痕：每轮写 `DecisionEntry`（轮次、阶段、假设、理由、效应）；artifact schema `mgba-autolab-artifact-0.1`，append-only、写一次。raw run 不重复落盘——同配置位级可复现，每次运行的 `history_digest` 作为审计锚点；未来接 WP9 reporting 时再补 raw。
7. 新增 `mgba autolab` CLI：注入真实评估器（基线运行按 `(seed, ticks)` 缓存，静态替换经 `_load_multirate_runner`），基线/条件逐 seed 配对跑 `_compare_runs`。
8. **LLM 预留接口**：`mgba autolab-propose --proposals <file>`。提案 = 注册表条目 schema + `proposed_by` 溯源字段；`validate_proposals` fail-closed（畸形内容只产生拒绝理由，不抛异常），**永不执行任何实验**；`accepted_for_registry_review` 仅表示"人有资格把它抄进注册表"。跳层类提案（如 `kind: "skip_l1"`、`layer: "L0"`）在 schema 层直接拒绝。
9. 新增 `tests/test_autolab.py`（18 项）：配置/假设 fail-fast、冻结筛选序、会话确定性、确认轮跟随探针测量（适应性）、效应标量绝对值语义、top-k 顺序、预算耗尽语义、评估器违约检测、提案门禁（接受/拒绝/碰撞/畸形/不执行）、真实 runner 复现基准。

## 结果

- 首次闭环会话 `autolab-71df3a1d06a63ce3`（默认演示场景，seed 41/42/43）：筛选轮（30 tick）效应 l1-static 0.010458、**l2-static 0.498391**、l3-static 0.216474；确认轮（100 tick）l2-static 0.4912。**调度器在 4 次评估内自主复现了 WP8 的冻结结论（L2 是最大杠杆点），且结论在 30→100 tick 地平线下稳健**——预注册复现基准通过。
- 提案门禁实测：合法 LLM 提案 `accepted_for_registry_review`；`skip_l1`/`L0` 跳层提案带理由拒绝；报告 `executed: false`。
- 基线缓存使命中率内基线运行从 12 次降到 6 次（3 probe + 1 confirm，各 3 seed）；整会话约 3 秒。
- 科学等级：方法论工具，不构成"自主科学发现"宣称；循环结论全部是 reference-model 级；循环自证与指标投机风险由冻结协议 + holdout 场景（合成基准）+ 远期真实数据锚定（`data/aivc/` 清单）缓解。
- 测试总数增至 239 项（221 + autolab 18），AGENTS §7 三条门禁全部通过；0.2.0 冻结身份位级不变（`test_frozen_identity` 通过）。

## 回退

删除 `mgba/autolab.py`、对应 CLI/配置/测试与文档条目即可回到 ADR-0019 状态；五层模型、全部实验矩阵与冻结基线不依赖本次新增代码。

## 后续阶段（未实施，各自需独立授权与 ADR）

- Phase 2：LLM 假设提出器——输出必须经 `autolab-propose` 门禁，prompt/输出进 manifest，人审后执行；需要 LLM API 授权与预算。
- Phase 3：真实数据锚定——按 `data/aivc/` 清单 Stage 1 起，让循环假设面对外部数据。
- 假设空间扩展（如 L0 钳制剂量、参数区间）：按需新增 kind，逐个 ADR 冻结。
