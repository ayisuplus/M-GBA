# ADR-0006：L4 第一版宏观表型观察器

> 状态：已接受  
> 日期：2026-08-18  
> 作用范围：WP6 L4 Organism / Phenotype reference model

## 背景与研究问题

当前 L4 只有写在 `multiscale.py` 中的三个聚合公式，没有独立配置、时间窗口指标、恢复能力或最终结局定义。WP6 要回答：

> 如何只从正式 `TissueState` 生成可解释、可复现且不会把预期答案写回 Cell 的宏观表型？

本工作包只升级 L4。L0–L3 保持稳定 reference model；L4→L3 慢反馈、多速率调度、因果消融和统计推断分别属于 WP7 之后的工作。

## 三类 L4 输出

L4 明确区分：

1. `OrganismState`：单个逻辑时间的即时宏观状态；
2. `PhenotypeWindow`：一段严格递增轨迹的描述性窗口摘要；
3. `OrganismOutcome`：只根据窗口终点和窗口变化得到的离散结局。

`PhenotypeModel.step` 仍只负责 `TissueState → OrganismState`，因此主生成链保持相邻层关系。窗口摘要是 L4 内部观察操作，不改变任何运行状态。

## 即时指标

所有输入和输出均在 `[0,1]`。下式中的量全部来自同一个正式 `TissueState`：

```text
vitality
  = mean_viability
    * (0.40 * mean_resource + 0.60 * (1 - tissue_damage))

damage_burden
  = tissue_damage

inflammation
  = 0.50 * tissue_damage
    + 0.30 * mean_activation
    + 0.20 * coordinated_signal

homeostasis
  = 0.45 * vitality
    + 0.30 * (1 - inflammation)
    + 0.25 * (1 - dead_fraction)

recovery_capacity
  = mean_viability
    * (
        0.50 * repair_activity
        + 0.30 * mean_resource
        + 0.20 * (1 - tissue_damage)
      )
```

解释边界：

- `vitality` 是活细胞比例在资源和损伤条件下能够支持的参考功能，不是真实器官功能测量；
- `damage_burden` 直接暴露 L3 已冻结的组织损伤，避免在 L4 重新发明另一套损伤定义；
- `inflammation` 是损伤、激活和协调信号的抽象组合，不对应细胞因子浓度；
- `homeostasis` 是活力、低炎症和低死亡的加权状态；
- `recovery_capacity` 表示当前仍存活组织在修复活动、资源和低损伤条件下的参考恢复潜力，不是预测疗效。

权重保存在独立 L4 JSON 配置中，每组非负且和为 1；模型版本包含完整配置摘要。

## 时间窗口

`PhenotypeWindow` 只接受由同一 L4 模型版本生成、逻辑时间严格递增且非空的 `OrganismState` 序列，保存：

- 窗口起止时间和样本数；
- 五个即时指标的窗口均值；
- 终点活力、稳态和损伤负担；
- `homeostasis_delta = final_homeostasis - initial_homeostasis`；
- 冻结的最终 `OrganismOutcome`。

这些量是描述性摘要。WP6 不进行显著性检验、不推断因果，也不把窗口摘要反馈给 L2。

## 最终结局

按以下优先级分类，阈值在批量实验前冻结：

```text
if final_vitality <= 0.20 or final_damage_burden >= 0.80:
    FAILED
elif final_homeostasis >= 0.70 and homeostasis_delta >= 0.05:
    RECOVERED
elif homeostasis_delta <= -0.05:
    DETERIORATING
else:
    STABLE
```

`FAILED` 优先，防止严重终点被短暂的正向变化掩盖。单样本窗口的变化量为 0，因此除非终点失败，否则归为 `STABLE`，不能声称恢复。

## 极端状态与方向性

冻结以下参考边界：

1. 完全存活、资源充足、无损伤/激活/信号/死亡且无主动修复时，活力和稳态为 1、损伤和炎症为 0、恢复能力为 0.5；
2. 完全死亡、资源耗尽、最大损伤/激活/信号和死亡比例时，活力、稳态和恢复能力为 0，损伤和炎症为 1；
3. 其他输入不变时，提高组织损伤不能提高活力、稳态或恢复能力；
4. 其他输入不变时，提高激活或协调信号只能提高炎症；
5. 其他输入不变时，提高修复活动只能提高恢复能力；
6. L4 收到非 `TissueState`、未来状态、混合模型版本或非递增窗口时必须失败。

## 备选方案

1. 继续保留三个内联公式：无法冻结配置、表达恢复或区分时间尺度，拒绝作为默认 L4。
2. 直接用单个“健康分数”：会隐藏损伤、炎症和恢复之间的权衡，拒绝。
3. 训练分类器预测结局：当前没有标注数据和外部验证，推迟。
4. 让 L4 读取 Cell 状态或 L0 扰动：破坏相邻层主生成流，禁止。
5. 在 WP6 同时实现 L4 反馈：会混合观察器和控制器职责，推迟到闭环工作包。

## 验收与失败判据

1. 同一 `TissueState` 和配置产生完全相同的 `OrganismState`；
2. 所有即时指标和窗口均值保持在 `[0,1]`，窗口变化量保持在 `[-1,1]`；
3. 健康/失败极端状态和各输入方向性满足冻结边界；
4. 四类结局均有独立测试，阈值边界按包含关系执行；
5. L4 API 只消费 `TissueState`，错误类型和未来状态失败；
6. 配置缺字段、权重长度错误、非有限值、越界或权重不和为 1 必须失败；
7. 配置变化必须改变 L4 `model_version`；
8. 默认五层 Runner 中 L0 修复敲低必须经 L3 后改变 L4，不允许 L4 读取扰动配置；
9. 静态旧 L4 以可注入基线保留，不覆盖新的 reference model。

## 影响、局限与回退

- `OrganismState` 增加 `damage_burden` 和 `recovery_capacity`；新增 `PhenotypeWindow` 与 `OrganismOutcome`。
- 默认 CLI 使用配置驱动的 L4 reference model；`ReferenceCrossScaleRunner()` 的无参契约回归仍使用静态 L4 基线。
- 指标由人为冻结的无量纲公式产生，未从真实生理数据拟合；不得用于生物学、临床或疗效结论。
- 若实验否定某个公式，必须发布新配置/模型版本并保留旧 artifact 的解释，不能静默改写结果。
