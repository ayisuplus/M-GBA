# ADR-0021：多数据集存放与多细胞类型交互约定（注册表 + 共培养验证）

> 状态：Accepted
> 日期：2026-08-21

## 背景

1. 所有者问题：项目目前只有 CAR-M 一种细胞/数据集；未来加入更多数据集、更多细胞类型时，(a) 数据集如何存放，(b) 不同细胞类型的关系与交互如何建模。
2. 读码结论：架构已支持多类型，缺的是约定与登记。`Genome`（`src/mgba/models.py`）只有 `version` + `traits`，无类型字段；`MultiscaleScenario`（`src/mgba/multiscale.py`）逐 agent 携带异构 genome，`configs/multiscale_demo.json` 四个细胞 genome 已各不相同。CAR-M（`src/mgba/scenarios/carm/scenario.py`）已是多群体编译先例：`CellRole` 枚举 + `CarmPopulation` 计数 + 每角色 genome 模板 + `_role_ids`/`_fixed_edges`。
3. 数据存放已有半成品惯例：`.gitignore` 覆盖 `data/raw/`；已入库数据为聚合/合成物（`data/carm/`、`data/synthetic-feedback/`）；计划中的外部资源走清单先行（`data/aivc/README.md`）。缺机器可读的统一登记与校验门禁。
4. 范围纪律：本 ADR 不改任何 L0–L4 DTO/Protocol/runner，不下载任何数据，不新建场景包代码；只固化约定、加登记门禁、用一个纯配置场景证明"L3 边介导跨类型交互"。

## 决定

1. **数据三级存放**：
   - 原始外部数据 → `data/raw/<name>/`（已被 `.gitignore` 覆盖，永不入库）；
   - 聚合 profile 与合成数据集 → `data/<name>/`（可入库，必须带来源/日期/SHA-256/许可/去标识声明；代理标签必须带 proxy notice，沿 `scenarios/carm/data.py` 的 `SourceArtifact` + `PROXY_LABEL_NOTICE` 先例）；
   - 计划中的外部资源 → 清单先行（`data/aivc/` 先例），下载须满足 AGENTS §6 三条件（明确用途、磁盘预算、用户授权）。
2. **登记义务**：每个入库数据集必须在 `data/registry.json`（schema `mgba-data-registry-0.1`）有一条目；`mgba data-check` 为 fail-closed 门禁——任一条目校验失败即打印报告并以 `SystemExit(1)` 退出。`src/mgba/data_registry.py` 提供 `DatasetEntry`/`DatasetProvenance`/`DatasetVerdict` 与 `load_data_registry`（fail-fast）/`validate_data_registry`（只出 verdict，不抛异常，由调用方决定失败时机）。`planned` 状态条目不得携带 sha256，文件可缺席；`materialized`/`generated` 必须登记 sha256 且实测一致。
3. **细胞类型 = L0 层概念**：类型身份只由 `Genome` 模板（traits/version）表达，可加可选群体 L0 钳制（CAR-M engineered vs wild-type 共享基础 Genome、差异经 L0 群体钳制传播的先例）。**禁止**向 L1–L4 DTO 添加任何类型标签字段。
4. **类型间交互只经 L3 两条通道**：固定有向图边（结构通道）+ 环境场（stress/resource/signal，场通道）。类型条件耦合参数只允许寄宿在场景 L3 模型的冻结配置中（`CarmTissueModel` 先例）。L2 永远只消费自身 `MolecularState` + `LocalEnvironment`，读不到他细胞的类型标签——跨类型影响必须经 L0→L1→L2→L3 链涌现，不允许 L3 把类型标签当上帝参数注入 L2。
5. **类型观测是观察层职责**：cell_id→role 映射由场景配置/编译器提供（`_role_ids` 先例），reporting/实验工具只读使用，不回写运行状态。
6. **新细胞类型/数据集准入清单**：逐条回答 AGENTS §2 六问 + §6 下载三条件，写进对应 ADR；答案不全记为候选想法，不进主干。
7. **纯配置共培养验证**：`configs/multiscale_coculture_demo.json`（12 细胞两种群：信号型 sig-1..6 与修复型 rep-1..6，群内有向环 + 4 条跨群边）证明第二种细胞类型只需新 Genome 模板与边，零契约变更。`tests/test_coculture_demo.py` 冻结三条性质：60 tick 位级确定性；类型差异经 L0→L1→L2 链涌现；跨类型影响经 L3 边介导（`dataclasses.replace(scenario, edges=<去跨群边>)` 后 rep 群 L3 signal 轨迹改变）。

## 结果

- `mgba data-check` 覆盖 3 条目（carm profile / synthetic-feedback manifest / aivc 计划清单），实测全部 `ok: true`；篡改 sha256 的登记实测 `ok: false` 且退出码 1（fail-closed 成立）。
- 共培养场景经 `mgba run` 跑通 L0→L4 契约路径（`trace_digest` 正常产出）；`MultirateCrossScaleRunner` 60 tick 双跑 `history_digest` 位级一致。
- 类型差异方向实测符合机制：L1 `signal_protein` 群体均值 sig > rep 全程成立（tick 60 为 0.234 vs 0.163）；L2 激活在存活窗口同向（tick 1 均值 0.155 vs 0.065）。**在 environment_stress 0.35 下两种群均在 tick 4 前进入 DEAD 吸收态**——与 100 tick reference 轨迹 `FAILED` 负面基线一致，属必须保留的参考模型行为；因此 L2 断言锚定存活窗口而非终 tick，不做任何调参。
- 边介导实测：去掉 4 条跨群边后 rep 群 L3 `signal` 逐 tick 轨迹改变且两 run `history_digest` 不同——跨类型影响走 L3 边而非类型标签，约定 4 在参考模型内成立。
- 测试总数 239 → 252（+13：registry 10、coculture 3）。
- 科学等级：本 ADR 全部是抽象 reference 层面的工程约定；类型模板不冒充真实细胞类型，共培养结果不构成任何生物真实性主张。

## 回退

删除 `data/registry.json`、`src/mgba/data_registry.py`、`configs/multiscale_coculture_demo.json`、对应 CLI 分支、两个测试文件与文档条目即可回到 ADR-0020 状态；五层模型、全部实验矩阵、CAR-M 场景包与 0.2.0 冻结身份不依赖本次新增代码。

## 修订 1（2026-09-15）：schema 0.2，许可与来源改为机器可读

> 依据：`AGENTS.md` §10.0 毕设收口期"允许并鼓励的工作"中的数据溯源增强项（推进计划 T0.4）。ADR 编号已冻结在 0050，本修订以追加形式记在本 ADR 内，不新建 ADR。

**为什么做：** 0.1 的 `provenance.license` / `provenance.source` 是自由文本，`mgba data-check` 只核验 SHA-256，无法机器回答"这条数据受哪些许可约束""它从哪条上游数据派生"。

**决定：**

1. `schema_version` 升至 `mgba-data-registry-0.2`，加载器只接受 0.2（fail-fast）。原有文本字段逐字保留，不改写历史措辞。
2. `provenance.license_ids`：非空、去重的受控词表。有 SPDX 标识的用 SPDX（`CC-BY-4.0`、`CC-BY-1.0`），没有的用 `LicenseRef-*`（MSigDB、GEO 公共数据、TCGA、Geneformer 仓库条款、旧 CAR-M 派生物、项目内部合成、按资源清单逐条）。词表定义在 `src/mgba/data_registry.py` 的 `ALLOWED_LICENSE_IDS`，词表外的标识一律拒绝。
3. `provenance.source_refs`：非空、去重，形如 `scheme:value`，scheme 只能取 `dataset`（另一条登记）、`doi`（须以 `10.` 开头）、`geo`（须为 `GSE` 编号）、`url`（须为 https）、`repo`（仓库内相对 POSIX 路径，不得含 `..`）。
4. 新增校验规则：
   - `aggregated_profile` / `external_raw` / `external_profile` 至少引用一个 `dataset` / `doi` / `geo` / `url` 来源，外部数据不能只指向仓库内文件；
   - 每个 `dataset:` 引用必须指向已登记的其他条目，且不得自引；
   - **许可传播**：下游条目的 `license_ids` 必须是全部 `dataset:` 上游 `license_ids` 的超集；
   - `repo:` 引用的路径必须实际存在（`validate_data_registry` 给出失败 verdict）。
5. `mgba data-check` 输出逐条目附带 `license_ids`；`mgba evidence-report` 同时接受 0.1 与 0.2 两种 registry schema。

**迁移结果：** 26 条目全部迁移，`mgba data-check` 26/26 通过。许可传播规则在迁移时暴露了一处散文遗漏：`aivc-d1-ood-split-manifest` 的散文许可逐项列出了 scPerturb / GEO / MSigDB，却漏了 Geneformer 条款，而该文件通过 `feature_eligibility.embedding_table_sha256` 依赖 Geneformer 嵌入表。另有 7 条（`aivc-d1-baseline-screen`、两份 `aivc-d1-interaction-evaluation`、两份 Hallmark 训练评估、两份嵌入评估）散文只写"随源数据"，同样依赖该嵌入表。结构化字段一律按上游保守取并集，显式带上 `LicenseRef-Geneformer`。原散文字段未改。

**连带变更：** 本修订改动 `src/mgba/*.py`，按 ADR-0045 / ADR-0050 §8 的既定通道更新源码指纹派生常量：单 tick 实验 ID `mgba-2cf0461e4813712f`、100 tick 实验 ID `mgba-7e9ffaa415f66163`、100 tick history digest `c073c47b…`。trace digest `20f95784…` 与 WP8 `matrix-7da4137aa39d5122` 实测不变，100 tick 结局仍为 `FAILED`。ADR-0050 提交时只更新了 `tests/test_frozen_identity.py`，漏掉了另外 6 处同源常量（`test_multiscale` / `test_demo` / `test_closed_loop` / `test_e3_statistics` / `test_neural` / `scripts/mvp_demo.py`），本次一并对齐。registry 字节变化后，`evidence-report --verify` 按设计判为不一致；旧报告已原样归档到 `artifacts/evidence-report/history/inputs-164bf6199fd40888/`，重建后 `verified=true`，除 registry 的 schema 与 SHA-256 外报告内容逐字节不变。

**回退：** 恢复 `data_registry.py`、`registry.json`、两处测试与 evidence-report 的 schema 白名单，再按同一通道回填指纹常量即可。数值轨迹与全部实验 artifact 不依赖本修订。

## 修订 2（2026-09-15）：`distribution` 分发标记与 D1 登记文件入库

**为什么做：** ADR-0047 的 8 个 D1-context-ood 登记文件整目录被 `.gitignore` 排除，干净 clone 与 CI 上 `mgba data-check` 必然失败（Core CI 自 2026-09-11 起的两项红灯即源于此）。其中两个 nadig 数据包派生自 GEO GSE264667，登记许可写明"无数据集级复用许可；保留署名、不再分发"，所以不能整体提交了事。所有者 2026-09-15 选定：提交可再分发的 6 个，nadig 两个只留本地。

**决定：**

1. 条目新增可选字段 `distribution`，取值 `repository`（默认）或 `local-only`，schema 版本仍为 0.2。`local-only` 只允许用于 `materialized` / `generated` 条目。
2. `local-only` 的语义：本地文件存在时照常核验 SHA-256，不一致即失败；文件缺失时给出 `ok: true`，并明确写出"local-only; not distributed with the repository, sha256 not checked here"，不静默跳过。`repository` 条目的行为不变。
3. 为防止拿 `local-only` 绕开门禁，`tests/test_data_registry.py` 把 `local-only` 条目集合钉死为这两个 nadig 包；以后要新增，必须改这条断言并说明许可依据。
4. `.gitignore` 改为白名单：D1 目录只放行 replogle 两个数据包、`ood-split-manifest.json`、`baseline-screen.json` 和两份 `interaction-evaluation*.json`，共约 11.2 MB。原始 h5ad、逐折预测、权重与 nadig 两个包继续忽略。`.gitattributes` 为 D1 目录加 `-text`，这些文件是 CRLF 字节，入库后跨平台 checkout 不会改动 SHA-256。

**结果：** 本地 `data-check` 26/26 通过，两个 nadig 包实测 `sha256 verified`。隐藏两个 nadig 包模拟干净 clone 时仍是 26/26，两条给出 local-only 说明。

**同批变更：** `src/mgba/lab.py` 与网站回放数据中"ADR-0043 calibration 确认 improved"和"→ calibration improved"两处文案，与本 ADR 所属项目在 ADR-0044 中的降级结论矛盾，已改为如实说明降级与 target 已消费。`mgba lab-export` 重建后，只有 `dose-response.json` / `catalog.json` / `manifest.json` 中的 `target_status` 及其派生摘要变化，另两套回放逐字节不变。两次源码改动合并后，指纹常量按通道更新为：单 tick `mgba-2c1963fa31d6a55c`、100 tick `mgba-e6a6d65dba732341`、history digest `7bd4d100…`。trace digest `20f95784…` 与 WP8 `matrix-7da4137aa39d5122` 不变。

**待所有者复核的不一致：** 同为 GEO 来源，`aivc-norman-geo-perturbation-profile`（GSE133344）已入库，散文许可也没有写"不再分发"，而 GSE264667 两个包写了。两者都是聚合派生物，许可立场是否应当一致，留给所有者判断，本修订不改动任何一条的许可记录。
