# ADR-0021：多数据集存放与多细胞类型交互约定（注册表 + 共培养验证）

> 状态：Accepted
> 日期：2026-08-21

## 背景

1. 所有者问题：项目目前只有 CAR-M 一种细胞/数据集；未来加入更多数据集、更多细胞类型时，(a) 数据集如何存放，(b) 不同细胞类型的关系与交互如何建模。
2. 读码结论：架构已支持多类型，缺的是约定与登记。`Genome`（`src/mgba/models.py`）只有 `version` + `traits`，无类型字段；`MultiscaleScenario`（`src/mgba/multiscale.py`）逐 agent 携带异构 genome，`configs/multiscale_demo.json` 四个细胞 genome 已各不相同。CAR-M（`src/mgba/scenarios/carm/scenario.py`）已是多群体编译先例：`CellRole` 枚举 + `CarmPopulation` 计数 + 每角色 genome 模板 + `_role_ids`/`_fixed_edges`。
3. 数据存放已有半成品惯例：`.gitignore` 覆盖 `data/raw/`；已入库数据为聚合/合成物（`data/carm/`、`data/synthetic-feedback/`）；计划中的外部资源走清单先行（`data/aivc/README.md`）。缺机器可读的统一登记与校验门禁。
4. 范围纪律：本 ADR 不改任何 L0–L4 DTO/Protocol/runner，不下载任何数据，不新建场景包代码；只固化约定、加登记门禁、用一个纯配置场景证明"L3 边介导跨类型交互"。

## 决定

1. **数据三级存放**：
   - 原始外部数据 → `data/raw/<name>/`（已被 `.gitignore` 覆盖，永不入库）；
   - 聚合 profile 与合成数据集 → `data/<name>/`（可入库，必须带来源/日期/SHA-256/许可/去标识声明；代理标签必须带 proxy notice，沿 `scenarios/carm/data.py` 的 `SourceArtifact` + `PROXY_LABEL_NOTICE` 先例）；
   - 计划中的外部资源 → 清单先行（`data/aivc/` 先例），下载须满足 AGENTS §6 三条件（明确用途、磁盘预算、用户授权）。
2. **登记义务**：每个入库数据集必须在 `data/registry.json`（schema `mgba-data-registry-0.1`）有一条目；`mgba data-check` 为 fail-closed 门禁——任一条目校验失败即打印报告并以 `SystemExit(1)` 退出。`src/mgba/data_registry.py` 提供 `DatasetEntry`/`DatasetProvenance`/`DatasetVerdict` 与 `load_data_registry`（fail-fast）/`validate_data_registry`（只出 verdict，不抛异常，由调用方决定失败时机）。`planned` 状态条目不得携带 sha256，文件可缺席；`materialized`/`generated` 必须登记 sha256 且实测一致。
3. **细胞类型 = L0 层概念**：类型身份只由 `Genome` 模板（traits/version）表达，可加可选群体 L0 钳制（CAR-M engineered vs wild-type 共享基础 Genome、差异经 L0 群体钳制传播的先例）。**禁止**向 L1–L4 DTO 添加任何类型标签字段。
4. **类型间交互只经 L3 两条通道**：固定有向图边（结构通道）+ 环境场（stress/resource/signal，场通道）。类型条件耦合参数只允许寄宿在场景 L3 模型的冻结配置中（`CarmTissueModel` 先例）。L2 永远只消费自身 `MolecularState` + `LocalEnvironment`，读不到他细胞的类型标签——跨类型影响必须经 L0→L1→L2→L3 链涌现，不允许 L3 把类型标签当上帝参数注入 L2。
5. **类型观测是观察层职责**：cell_id→role 映射由场景配置/编译器提供（`_role_ids` 先例），reporting/实验工具只读使用，不回写运行状态。
6. **新细胞类型/数据集准入清单**：逐条回答 AGENTS §2 六问 + §6 下载三条件，写进对应 ADR；答案不全记为候选想法，不进主干。
7. **纯配置共培养验证**：`configs/multiscale_coculture_demo.json`（12 细胞两种群：信号型 sig-1..6 与修复型 rep-1..6，群内有向环 + 4 条跨群边）证明第二种细胞类型只需新 Genome 模板与边，零契约变更。`tests/test_coculture_demo.py` 冻结三条性质：60 tick 位级确定性；类型差异经 L0→L1→L2 链涌现；跨类型影响经 L3 边介导（`dataclasses.replace(scenario, edges=<去跨群边>)` 后 rep 群 L3 signal 轨迹改变）。

## 结果

- `mgba data-check` 覆盖 3 条目（carm profile / synthetic-feedback manifest / aivc 计划清单），实测全部 `ok: true`；篡改 sha256 的登记实测 `ok: false` 且退出码 1（fail-closed 成立）。
- 共培养场景经 `mgba run` 跑通 L0→L4 契约路径（`trace_digest` 正常产出）；`MultirateCrossScaleRunner` 60 tick 双跑 `history_digest` 位级一致。
- 类型差异方向实测符合机制：L1 `signal_protein` 群体均值 sig > rep 全程成立（tick 60 为 0.234 vs 0.163）；L2 激活在存活窗口同向（tick 1 均值 0.155 vs 0.065）。**在 environment_stress 0.35 下两种群均在 tick 4 前进入 DEAD 吸收态**——与 100 tick reference 轨迹 `FAILED` 负面基线一致，属必须保留的参考模型行为；因此 L2 断言锚定存活窗口而非终 tick，不做任何调参。
- 边介导实测：去掉 4 条跨群边后 rep 群 L3 `signal` 逐 tick 轨迹改变且两 run `history_digest` 不同——跨类型影响走 L3 边而非类型标签，约定 4 在参考模型内成立。
- 测试总数 239 → 252（+13：registry 10、coculture 3）。
- 科学等级：本 ADR 全部是抽象 reference 层面的工程约定；类型模板不冒充真实细胞类型，共培养结果不构成任何生物真实性主张。

## 回退

删除 `data/registry.json`、`src/mgba/data_registry.py`、`configs/multiscale_coculture_demo.json`、对应 CLI 分支、两个测试文件与文档条目即可回到 ADR-0020 状态；五层模型、全部实验矩阵、CAR-M 场景包与 0.2.0 冻结身份不依赖本次新增代码。
