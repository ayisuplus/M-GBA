# ADR-0010：WP10 MVP 交付冻结

> 状态：已接受  
> 日期：2026-08-18  
> 作用范围：0.1.0 交付候选、报告、演示、复现与版本边界

## 背景

WP0–WP9 已形成可运行的 L0→L4 reference model、多速率 Runner、配对扰动/消融矩阵与 raw-only 报告链。WP10 的任务是冻结这一证据面，而不是为演示继续加入 GNN、LLM Agent、动态拓扑或新参数。

## 决策

### 1. 版本身份

交付候选版本固定为 `0.1.0`，`pyproject.toml` 和 `mgba.__version__` 必须一致。这是本科毕设长期项目的第一个 reference-model MVP，不是 1.0 生物学模型。

仓库尚无首次 Git commit，因此 WP10 只准备 release candidate 内容；必须在用户审查并授权首次 commit 后才创建 `v0.1.0` tag。不允许对一个尚未审查的未跟踪工作树伪造发布标记。

### 2. 完整演示与降级演示

`scripts/mvp_demo.py --mode full` 是冻结的完整演示：

1. 运行单 tick L0→L4 契约链；
2. 运行 100 tick 多速率基线；
3. 运行并保存 21-run WP8 矩阵；
4. 只从 raw artifact 重建 WP9 报告；
5. 对冻结的 ID、历史摘要、结局和文件数量做失败即停校验。

`--mode fallback` 只运行契约链、30 tick Runner 与独立 STEN smoke。它用于受限演示环境，不生成 WP8/WP9 证据，不能代替完整复现。

### 3. 报告与数字追溯

交付包含中文设计报告、英文技术报告、复现说明和发布清单。任何结果数字必须指向以下一项或多项：

- 实验 ID 或 matrix ID；
- 历史哈希链摘要；
- raw artifact 相对路径；
- report manifest 中的 SHA-256。

不将三个数值相同的 seed 写成独立统计重复，不报告 p 值、置信区间或涌现稳定性。

### 4. 空环境验收

复现环境必须：

- 使用 Python 3.11 或更高版本的新虚拟环境；
- 在具有 `setuptools>=68` 的构建环境产生 wheel，再以 `pip install --no-deps --no-cache-dir <wheel>` 安装到空虚拟环境；
- 不依赖网络、GPU、Notebook 或第三方运行时库；
- 通过全部单元测试和 full demo；
- 保存安装环境、命令、结果 ID 和已知限制。

## 验收

1. 版本号一致；
2. 新环境安装成功；
3. 全部测试通过；
4. full demo 产生冻结的 experiment/matrix ID 与 10 个报告文件；
5. fallback demo 明示其证据范围；
6. README 能引导新用户运行基线、扰动、报告与测试；
7. 中英文报告对科学边界的表述一致。

## 后果

- 交付面可以在无 GPU、无网络的 CPU 环境复现。
- 0.1.0 的证据范围被冻结，后续新模型必须以新版本与当前 reference baseline 对照。
- Git commit/tag 保持为审查后的明示操作，不由自动化默认代替用户决策。
